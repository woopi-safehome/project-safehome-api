# deed — 등기부등본 분석 도메인

업로드된 문서를 비동기로 분석하고, 진행 상황을 실시간으로 알리고, 결과와 이력을 관리한다.

> **범위**: `domain/deed/**`
> **상위**: [`domain/README.md`](../README.md) (레이어 규칙) · [API README](../../../../../../../../README.md)
> **연관**: 캐시 정책 → [`docs/llm-cache-strategy.md`](../../../../../../../../docs/llm-cache-strategy.md) · 엔드포인트 스펙 → 저장소 README의 **App→API 계약** 절
> **여기 없는 것**: 클래스·포트·메서드 목록 — 디렉터리와 코드가 답한다.

---

## 책임과 경계

| 이 도메인이 답하는 것 | 답하지 않는 것 |
|---|---|
| 이 문서를 분석해 달라 | 무엇이 위험한가 (AI 분석 서버 소관) |
| 지금 어디까지 진행됐나 | 화면에 어떻게 보일까 (앱 소관) |
| 내가 맡긴 분석의 이력 | 누구에게 알림을 보낼 수 있나 (인증 도메인 소관) |

**판정하지 않는다.** 분석 결과를 받아 저장하고 통과시킬 뿐, 내용을 해석하지 않는다.

---

## 관통 흐름

업로드 요청은 **작업을 만들고 즉시 식별자를 돌려준다.** 분석은 그 뒤 별도 스레드에서 진행된다.
클라이언트는 식별자로 진행 상황을 구독하거나 나중에 결과를 조회한다.

```
업로드 → 작업 생성(대기) → [응답: 식별자]
                              ↓ 트랜잭션 커밋 후 비동기 시작
          문서 검증 → 텍스트 추출 → 분석(캐시 확인 후 필요할 때만 외부 호출)
          → 요약 정보 추출 → 결과 저장(완료) → 진행 알림 → 푸시 발송
```

각 단계 전환마다 구독 중인 클라이언트에게 상태를 밀어 보낸다.
상태와 단계의 허용값은 저장소 README의 계약 절에 있다.

## 불변식

- **비동기 작업은 트랜잭션이 커밋된 뒤에 시작해야 한다.**
  먼저 띄우면 그 스레드가 **아직 존재하지 않는 작업을 조회**한다. 타이밍에 따라 되기도 해서 재현이 어렵다.
- **구독이 늦어도 결과를 놓치지 않는다.** 구독 시점에 작업이 이미 끝나 있으면
  최종 상태를 즉시 보내고 연결을 닫는다. 이 처리가 없으면 **빠르게 끝난 분석에서 클라이언트가 영원히 기다린다.**
- **남의 작업은 볼 수 없다.** 조회·구독 모두 요청자와 작업 소유자가 같은지 확인한다.
  식별자를 알아도 접근할 수 없어야 한다.
- **비회원 작업은 업로드한 브라우저만 볼 수 있다.** 회원이 없을 뿐 주인은 있다 —
  익명 쿠키가 그 주인이다. 등기부에는 주소와 소유자 이름이 들어 있어,
  **식별자만으로 열면 링크가 새는 순간 그대로 노출된다.** 쿠키가 다르면 회원이라도 막는다.
  > 쿠키를 지우거나 다른 브라우저로 옮기면 **자기 분석도 다시 볼 수 없다.** 이력을 남기려면 로그인해야 한다.
  > **익명 쿠키는 인증이 아니다.** 브라우저를 구분할 뿐이고, 누구인지는 알지 못한다.
- **주인이 아예 없는 작업은 식별자가 열쇠다.** 익명 쿠키를 쓰기 전에 만들어진 것들이라
  확인할 기준이 없다. 새로 만들어지는 작업에는 해당하지 않는다.
- **이력 목록은 비회원에게 열지 않는다.** 익명 쿠키로 묶을 수는 있지만 그러지 않는다 —
  쿠키는 지워지고 기기 사이를 넘지 못해 **이력이라 부를 만큼 남지 않는다.** 이력은 로그인의 몫이다.
- **회원은 하루에 정해진 횟수만 분석을 시작할 수 있다.** 계정 기준이고, 하루의 경계는 서버의 자정이다 —
  24시간 전부터 세면 어제 늦게 쓴 사람이 오늘 종일 막힌다.
  **실패한 분석은 세지 않는다.** 사용자 탓이 아닌 실패로 하루치를 잃으면 안 되기 때문이다.
  진행 중인 것은 센다 — 세지 않으면 끝나기 전에 여러 건을 한꺼번에 밀어 넣을 수 있다.
  **막을 때는 작업을 만들지 않는다.** 남겨 두면 이력이 더러워지고 분석 비용도 나간다.
- **비회원은 요청 주소를 단서로 세고, 비회원 전체에도 천장을 둔다.**
  주소는 바꿀 수 있다 — VPN 이나 회선 전환이면 그만이므로 주소 제한만으로는 비용이 닫히지 않는다.
  **천장이 그 몫을 한다.** 반대로 천장만 두면 한 사람이 남의 몫까지 쓸 수 있어 둘이 같이 있어야 한다.
  **시크릿 모드는 이 제한을 비껴가지 못한다** — 주소가 그대로이기 때문이다.
  **회원은 이 천장에 세지 않는다.** 비회원이 몰려도 회원의 하루치는 남아 있어야 한다.
  주소별로 먼저 막고 나서 천장을 센다. 순서가 반대면 거절당할 요청이 천장을 깎는다.
- **비회원 사용량을 셀 수 없으면 막는다.** 캐시와 **반대로** 다루는 자리다 —
  캐시는 없어도 결과가 같지만, 이 천장은 **비용의 유일한 보장**이라 세지 못하는 동안 열어 두면
  보장 자체가 사라진다. **회원은 이 길을 지나지 않으므로** 저장소가 흔들려도 로그인한 사용자는 그대로 쓴다.
- **주소를 알 수 없어도 천장은 센다.** 주소가 없다고 통과시키면 헤더를 지우는 것만으로 천장을 비껴간다.
- **주소를 그대로 저장하지 않는다.** 해시만 남기고 날짜가 바뀌면 키 자체가 바뀐다.
- **앞단을 거친 요청은 전달 헤더의 주소를 쓴다.** 연결 주소를 그대로 쓰면 프록시 뒤에서
  **모든 비회원이 한 주소로 보여 첫 한 건 뒤로 전부 막힌다.** 웹 프론트가 이 구성이다.
  **헤더는 연결 상대가 사설망일 때만 믿는다** — 헤더는 누구나 붙일 수 있어서, 인터넷에서 직접 온
  요청이 붙인 것은 무시한다. 프록시를 사설망 밖에 두면 이 판단이 틀리므로 배치를 다시 봐야 한다.
  > 이 주소는 인증이 아니다. 우회되어도 **전체 천장이 비용을 막는다.**
- **작업은 실패해도 남는다.** 실패 상태와 사유를 기록한다. 조용히 사라지면 사용자가 원인을 알 수 없다.
  비동기 처리는 요청 스레드 밖이라 예외를 받아 줄 곳이 없으므로, **결과를 만드는 단계에서 예상하지 못한 예외가 나도**
  실패로 기록하고 구독자에게 끝을 알린다. 실패 기록조차 실패하면 로그만 남는다.

## 실패를 어떻게 다루는가

| 무엇이 실패하면 | 어떻게 되나 |
|---|---|
| 문서 검증 | 작업을 실패로 기록하고 사유를 남긴다. 사용자에게 보이는 실패다 |
| 텍스트 추출 | **섹션을 못 찾아도 실패하지 않는다.** 빈 섹션이 그대로 넘어가고, 등기부가 맞는지는 분석 서버가 판정한다. 파일 자체를 읽지 못하면 실패로 기록한다 |
| 캐시 | **무시한다.** 미스처럼 취급하고 외부 호출로 넘어간다 |
| 비회원 사용량 집계 | **막는다.** 비회원 업로드를 거절한다 — 천장이 비용의 유일한 보장이라 열어 둘 수 없다. 회원은 영향받지 않는다 |
| 외부 분석 서버 | 작업 실패. 다만 타임아웃을 두어 요청이 매달리지 않게 한다 |
| 결과 저장 | 작업 실패 |
| 알림 스트림 끊김 | **정상으로 본다.** 클라이언트가 먼저 끊는 경우가 흔하다. 에러로 처리하면 로그가 오염된다 |
| 완료 알림 (진행 알림·푸시 대상 조회·발송) | **무시한다.** 결과 저장이 끝난 뒤에 보내므로, 알리는 일이 실패해도 완료를 되돌리지 않는다 |

원칙은 하나다 — **결과를 만드는 일은 실패로 다루고, 결과를 알리는 일은 실패해도 넘어간다.**
문서 해석 실패, 분석 서버 실패, 알림 대상 조회 실패는 실행 테스트가 고정한다.

**예외가 하나 있다 — 발송 실패 중 "이 기기는 더 이상 없다"는 응답은 버리지 않는다.**
발송 서비스가 만료된 대상이라고 알려주면 그 대상을 저장소에서 지운다.
지우지 않으면 **없는 기기에 계속 발송을 시도하고, 그때마다 같은 실패가 반복된다.**
무엇이 그 신호인지는 발송 서비스가 정하는 대외 계약이므로, 그 쪽 문서가 원본이다.

## 설계 결정

**분석 결과를 캐시한다.** 같은 문서를 다시 올리면 외부 호출을 건너뛴다.
**무엇이 같은 요청인지는 문서 내용만으로 정해지지 않는다** — 키 구성과 무효화 정책은
[`docs/llm-cache-strategy.md`](../../../../../../../../docs/llm-cache-strategy.md)가 갖는다. 여기 복제하지 않는다.

이 도메인이 알아야 할 것은 하나다 — **상류의 프롬프트나 판정 기준이 바뀌면 캐시를 비워야 한다.**
비우지 않아도 아무 에러가 나지 않고 옛 결과가 계속 나간다.

**완료 시 결과에서 요약 정보를 뽑아 별도 컬럼에 저장한다.** 이력 목록에서 결과 전문을 파싱하지 않기 위해서다.
결과 구조가 바뀌면 이 추출도 함께 봐야 한다.

**다른 도메인의 데이터는 포트로 가져온다.** 알림 대상을 알아내야 하지만,
상대 도메인은 이 도메인의 존재를 모른 채로 남는다.
